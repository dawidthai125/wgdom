## 1. Zasady wiążące (kontynuacja NG-04)

Principles **#001**, **#002**, **#003** z [`NG-04-DESIGN-FREEZE.md`](NG-04-DESIGN-FREEZE.md) pozostają **w pełni obowiązujące**. NG-04.2 dodaje **#004** i **#005**.

### 1.1 NG-04 Principle #004 — Benchmark is Presentation

> **Status:** **WIĄŻĄCE** od NG-04.2.

| Reguła | Znaczenie |
|--------|-----------|
| **Brak nowego modelu** | Zakaz pól `benchmark*` w `KosztorysBoqRowViewModel` i w snapshot |
| **Tylko istniejący ViewModel** | Benchmark czyta `row.pricing` (`laborPlnPerUnit`, `categoryId`, `unit`) już osadzone w BOQ ViewModel |
| **Prezentacja ≠ merge** | `compareLaborRateToBenchmark` wywoływany w **warstwie widoku** lub w **pure view helperze** — nigdy w `buildKosztorysBoqExplorerView` |
| **Jeden algorytm** | Wyłącznie `labor-benchmark.ts` — zakaz drugiego silnika |
| **Ukryj gdy brak sensu** | `UNKNOWN`, `unavailable`, `laborPlnPerUnit ≤ 0` → brak badge (nie „—” jako fałszywy status) |

```text
KosztorysBoqRowViewModel.pricing  (już w ViewModel od 04.1)
              │
              ▼
   resolveBoqRowLaborBenchmark()   ← pure helper, NIE część ViewModel
              │
              ▼
   compareLaborRateToBenchmark()   ← SSOT algorytm (frozen import)
              │
              ▼
   buildBoqLaborBenchmarkCache()   ← derived cache (#005)
              │
              ▼
   BoqLaborBenchmarkBadge          ← UI adapter (lookup only)
              │
              ▼
   LaborBenchmarkStatusBadge       ← React presentation only
```

**Zakazy (#004):**
- `benchmarkStatus` / `laborBenchmark` na `KosztorysBoqRowViewModel`
- Precompute benchmarków w `useMemo` zależnym od `searchQuery` w sposób wołający merge
- Dziedziczenie statusu z `categorySummary` zamiast stawki **linii**
- Nowy typ `BoqBenchmarkViewModel` / równoległy store

### 1.2 NG-04 Principle #005 — Derived UI Cache

> **Status:** **WIĄŻĄCE** od NG-04.2.

| Reguła | Znaczenie |
|--------|-----------|
| **Źródło** | Benchmark wyliczany wyłącznie z gotowego `KosztorysBoqRowViewModel[]` (`view.rows`) |
| **Warstwa** | Obliczenia w **prezentacji** — `buildBoqLaborBenchmarkCache` + `useMemo`; nie w merge lib |
| **Bufor** | `ReadonlyMap<rowKey, LaborBenchmarkComparison>` budowany **raz** per zmiana `view.rows` |
| **Search / filter** | `filterKosztorysBoqRows` **nie** woła resolve; wiersz robi **lookup** w istniejącej Map |
| **Invalidacja** | Tylko gdy `view.rows` reference się zmieni (nowy `item`, overrides → rebuild ViewModel) |

```typescript
// KosztorysBoqExplorerSection — wzorzec freeze
const benchmarkCache = useMemo(
  () => buildBoqLaborBenchmarkCache(view.rows),
  [view.rows],
);

const filteredRows = useMemo(
  () => filterKosztorysBoqRows(view.rows, { query, categoryFilter }),
  [view.rows, query, categoryFilter],
);
// benchmarkCache NIE w deps filteredRows
```

**Zakazy (#005):**
- `resolveBoqRowLaborBenchmark` w `filterKosztorysBoqRows` lub w pętli search handlera
- Rebuild cache przy każdej zmianie `searchQuery` / `categoryFilter`
- `useMemo` cache z deps `[view.rows, searchQuery]` — niedozwolone
- Per-row `useMemo` × 500 w `BoqLaborBenchmarkBadge` zamiast wspólnej Map

### 1.4 NG-04 Principle #006 — UI Consumes Cache Only

> **Status:** **WIĄŻĄCE** od NG-04.2.

| Reguła | Znaczenie |
|--------|-----------|
| **UI bez resolve** | Komponenty React **nigdy** nie wołają `resolveBoqRowLaborBenchmark()` |
| **Jedyny builder** | Benchmark wyliczany **wyłącznie** w `buildBoqLaborBenchmarkCache()` |
| **Lookup only** | UI korzysta tylko z `cache.get(rowKey)` |
| **Jeden adapter** | `BoqLaborBenchmarkBadge` jest **jedynym** mostem cache → `LaborBenchmarkStatusBadge` |
| **Zakaz w React** | Zabronione wyliczanie benchmarków w komponentach React (w tym inline `compareLaborRateToBenchmark`) |

**Zakazy (#006):**
- `resolveBoqRowLaborBenchmark` w `.tsx` (poza testami)
- `compareLaborRateToBenchmark` w `KosztorysBoqRowFields`, `KosztorysBoqExplorerSection`, `BoqLaborBenchmarkBadge`
- Osobny komponent badge poza `BoqLaborBenchmarkBadge`
- `buildBoqLaborBenchmarkCache` w `useMemo` z deps `[view.rows, searchQuery]`

### 1.6 NG-04 Principle #007 — Presentation Metadata Only

> **Status:** **WIĄŻĄCE** od NG-04.2 release · obowiązuje kolejne fazy prezentacji (NG-04.3+).

| Reguła | Znaczenie |
|--------|-----------|
| **Brak rozszerzenia ViewModel** | Dane prezentacyjne (tooltipy, confidence, FOUND_NO_VALUE, AI hints, explanation) **nie** rozszerzają `KosztorysBoqRowViewModel` |
| **Derived metadata** | Warstwa prezentacji może budować własne metadane na podstawie istniejącego ViewModel (jak cache benchmarków) |
| **Kontynuacja #001–#006** | Pełna zgodność z Principles #001–#006 — #007 dotyczy przyszłych warstw UI, nie merge |

**Przykłady (NG-04.3+):** tooltip ATH FOUND_NO_VALUE, expanded `LaborBenchmarkCell` — osobna Map/cache prezentacji, nie nowe pola w `KosztorysBoqRowViewModel`.
